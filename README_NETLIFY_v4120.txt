ジャグラー設定判別 v4.1.2 / Netlify配置メモ

デプロイ先: https://jugest.netlify.app

v4.1.2 の変更
- v4.1.1の「30日以上の通常取得後に固定30分ロック」を廃止。
- Launcherの通常取得・夜間取得を共通で、直近30分間のana-sloネットワークアクセスを最大30回に制限。
- 30回目までは取得でき、31回目を出す直前に最古アクセスが30分経過するまで自動待機。30分経過ぴったりで1枠復活し、そのまま自動再開する。
- HTTP成功だけでなく、403/429・5xx・通信失敗など、実際にana-sloへ送った取得試行はすべて1アクセスとして記録。夜間モードの再試行も同じカウンタを使う。
- JSONのNetlify送信/Launcher連携はana-sloアクセスではないためカウント対象外。
- アクセス履歴はana-slo側localStorageに加え .ana-slo.com 共有cookieにも保持し、ページ更新・Safari再起動・店舗変更・ana-slo/www間の移動でリセットされにくい構成。
- 上限到達時はLauncherに「30/30」と残り時間を表示。停止中は開始ボタンをロックし、実行中は自動待機して枠復活後に再開。
- 通常取得の既存待機、夜間取得の35〜55秒/日・15日/60日休憩・エラー時長時間再試行はそのまま残る。
- parserVersionは4070据え置き。v4.0.7以降の正常取得データは再取得不要。
- ジャグラーデータ、JSON出力/中継、設定判別、店舗解析、予測、Calibration、移動判断は変更なし。

デプロイ
ZIPのプロジェクト全体（package.json / netlify.toml / netlify/functions / public）をNetlifyでビルド・デプロイする。publicだけの配置ではrelay Functionが動かない。

Safariブックマーク
BOOKMARKLET_v4120.txt の1行をURL欄へ貼る。

運用イメージ
- 例: 5分で30アクセス消費した場合、次の取得は最初のアクセスから30分経過するまで約25分自動待機。
- 例: 30アクセスに25分かかった場合、約5分待てば1枠復活。
- ヒロ側で30分を計る必要はない。Launcherが直近30分の履歴から自動管理する。

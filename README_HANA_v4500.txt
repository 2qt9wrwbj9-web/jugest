2026-08-25

■ v4.5.0
既存 v4.1.2 系統を保ったまま、ハナハナ5機種を本体へ統合。

対応ハナハナ
- ハナハナホウオウ～天翔～
- キングハナハナ
- ドラゴンハナハナ～閃光～
- スターハナハナ
- ニューキングハナハナV

■ UI
- 大タイトル: ジャグラー・ハナハナ設定判別
- 実戦判別 / 後ヅモ用で JUGGLER / HANA HANA 切替
- 店舗データ: ジャグラー・ハナハナデータ
- 台比較: ジャグラー8 + ハナハナ5 = 13機種を機種横断比較
- 移動比較: ジャグラー ↔ ハナハナの機種横断比較に対応

■ ハナハナ後ヅモ
G / BIG / REG / 差枚を使用。
実測ベルが無い場合は差枚からベル確率を逆算し、ベルを一点決めせず尤度として統合。
前任者の打ち方は後ヅモ側のみ。判別開始時点で着席前スナップショットとして固定。

■ ハナハナ実戦判別
着席後に自分が観測したものだけを追加入力。
- 自分の通常G / BIG / REG
- 実測ベル
- BIG中スイカ / ハズレ（対象ゲーム数で計算）
- サイドランプ
- BIG後ランプ
- REG後ランプ
- レトロサウンド
- ニューキングハナハナV: REG中スイカ

ランプ種別は完全分離。
ランプ数は対応する自分のBIG/REG回数と照合し、不整合な要素は判別から除外。
設定変更後の初回BIGランプは別カウントで、通常BIG後ランプの尤度には混ぜない。
REG後の「濃厚」示唆は下位設定を0%にするハード制約。
ニューキングハナハナVは V=5 として期待設定を計算。

■ Launcher / Ana-slo
PARSER_VERSION=4500。
ジャグラー8機種 + ハナハナ5機種を取得。
30φ / 25φ / スマート沖スロなど、同一機種の表記違いは canonical machine ID に統合。
元の表記 sourceMachineName は保存する。
未認識の「ハナハナ」表記は黙って捨てず警告する。

旧 parser 4070 の Launcher キャッシュは v4.5.0 では再利用しない。
これは以前取得済みの日を「ジャグラーだけ取得済み」と誤認してハナハナを取り逃さないため。
ツール本体に既に取り込んだ旧ジャグラーデータ自体は消さない。同店舗・同日を新しい13機種JSONで受信すると、その日を更新できる。

■ 取得レート制御
v4.1.2 の「直近30分で最大30 Ana-sloアクセス」を維持。
30回目までは許可し、31回目の前で最古アクセスが30分を越えるまで自動待機。

■ 本体設計
ジャグラー判別式とハナハナ判別式は独立。
上位の店舗解析へは共通の設定分布として渡す。
ニューキングハナハナVは共通6スロット内部表現では V を設定5スロットへ置き、設定6スロットを常に0にする。

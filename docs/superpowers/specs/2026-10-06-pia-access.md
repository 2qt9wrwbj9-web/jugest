# 管理者パスキーとPIA閲覧招待

依頼の目的は、ヒロが本人確認を行って共有を管理し、招待された人がPIA収集データだけを期限付きで閲覧できること。判別数学、収集、既存所有者認証、一般公開の設定判別は変更しない。本番変更は禁止。

開始時の本番配信は `04fc937a852c77004fe3f7fa9bb163b07d0cf234`、未管理ファイルなし。主要サーバーファイルのSHA-256もGitHubと一致。調査ブランチへこの系列をローカルに統合して既存のUI改良を保持した。本番ブランチは変更していない。

## 境界

- Node.js HTTPサーバー、組み込みSQLiteに追加する。認証専用DBは既定 `/var/lib/jugest/access.sqlite`。既存の正規DB・Relay DBへmigrationを加えない。
- 管理者はWebAuthn、本人確認必須、公開鍵・認証情報のみ保存。同期するパスキーを物理端末固定と表現しない。
- 管理者セッションは12時間、重要操作には5分以内の本人確認。PIAセッションと管理者セッションは別Cookieで、Secure、HttpOnly、SameSite=Strict、Path=/、Domainなし。
- WebAuthn検証はSimpleWebAuthn、認証先URLとドメイン識別子を固定設定して完全一致検証。Originをリクエストから推測しない。
- 初回CLIトークンは15分、256ビット、1回限り、既存credentialがあれば初回bootstrapは拒否。端末追加は再認証済み管理者が同じ形式のトークンを発行。紛失時復旧はサーバーCLI限定。
- 招待コードは128ビット、1回、入力期限30分、閲覧24時間。発行時にメモ・期限・閲覧時間を指定。生コードは発行応答1回だけ。
- 招待消費と閲覧セッション作成を1つのSQLiteトランザクションで確定。セッションは別の256ビット乱数。DBにはトークンのSHA-256のみ。
- credential失効で既存の管理者セッションとそのcredentialが発行した未使用の管理者追加トークンを失効。閲覧セッションは毎回DBの有効性を確認。招待無効化は、その招待の閲覧セッションも停止する。
- 管理者のCookieにもPIA閲覧を許可するが、既存のCollector管理権限へは昇格しない。
- 既存 `/api/vps/stores` と日別取得にPIA限定の閲覧認証を追加。店舗リストはPIAのみ、店舗IDを交換して他店を読むことは禁止。解析、予測、管理、収集、認証済み設定判別のAPIへは新しいCookieを認めない。
- 共有有効時は旧PIAのownerモードと非空の所有者許可リストを必須にし、不適合なら起動を拒否。旧publicモードを招待制に併存させない。共有無効時の旧ポリシーは維持する。
- 管理一覧には有効な招待・閲覧を全件含め、直近200件の履歴も含める。有効な停止対象を履歴で隠さない。接続元で拒否した試行で全体rate枠を減らさない。
- MCPの既存認証は変更せず、`judge_machines` と `/api/public/judge` の一般公開を維持。
- `/admin/login`、`/admin/register`、認証後の `/admin`、`/pia/access`、認証後の `/pia`。表示は既存の色・余白を踏襲し、動的文字列にはtextContentを使用。
- 状態変更はJSON POST、専用ヘッダー、固定Originとの照合を必須とする。Cookie認証へCORS許可を加えない。
- 認証・招待APIにDBの短期rate limit。IPの生値を保存せず、短期の照合識別子と全体上限を使う。監査履歴はtokenを含めず90日保存。
- 静的配信にデータ・バックアップ拡張子と保存用ディレクトリの拒否を追加。公開ディレクトリ内へ認証DBや原本を配置できないよう確認。

## 本番調査の限界

接続ユーザーには `/var/lib/jugest` とプロセス環境を読む権限がない。権限昇格コマンドは接続ツールで拒否された。これを迂回せず、実DBスキーマ・プロセス環境名の完全確認は本番反映前の未完了事項にする。既存DBと別ファイルのmigrationを採用するため、既存データを移す必要はない。

インストール済みデプロイヤーは配信中のものと異なる。差分はテスト前の依存導入条件、エラー表示、検査など。監視対象と切替方式は同じ。既存インストール版も `vps/package-lock.json` が存在すれば `npm ci` するため、今回の依存導入にロックファイルを同梱する。本番のデプロイヤーを変更しない。

## 成功条件

失効・期限・再利用・競合・所有者継続・PIA限定認可・未認証直接取得拒否・Origin/RP ID/本人確認・秘密値非保存を自動検証する。既存2 suiteを通し、仮想認証器によるWebAuthn検証も実施する。独立したレビュー担当が攻撃者視点で全差分を確認する。最後に未完了の本番確認を含めて報告し、本番反映を行わず停止する。

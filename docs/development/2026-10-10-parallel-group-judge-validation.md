# 並列判別・全台系 検証記録

開発基準は `f728b2587a9bdd81541ccb50d3ae802a8492486a`、開発ブランチは `work/parallel-group-judge-20261010`。本番VPSのcurrentと判別関連5ファイルを読み取りで照合した。deploy/vps・main・本番サービス・本番データの変更は今回の範囲に含めない。

## 調査した既存設計

`index.html` の `externalJudge`／`externalBonusJudgeQ`／`reverseCoreKnown`／`reverseCore` と機種別表、`judgement-model.js` の観測入力adapter・診断値、`judgement-view.js` と `app-v510.js` の入力・個別結果・詳細導線を確認した。現在の設定分布は6設定の等重み正規化。BB・RB・その他の多項尤度と、差枚がある場合の既存ブドウ逆算の近似を使う。既存ログを新エンジンに渡し、丸められた事後分布から尤度を復元しない。

店舗予測側の `v4ModelTraining` は時系列のdiscovery／confirm／scoreに分割し、`v4FitCalibration` は既存 `r.p4` を目標 `y` とする予測補正を行う。確定設定や全台系イベントの正解ラベルによる校正ではないため、これを全台系の成立事前頻度や成立確率の根拠に流用しない。strict Champion・Calibration・store-share constraint・single-evidenceの既存実装を保持した。

従来のsingle-evidence設計では、同じ観測を別の集計や表現へ変えて独立根拠として重ねない。この原則に合わせ、各台・合算・ボーナスだけの再計算・反証検査を独立証拠として乗算しない。既存のpreservation・個別画面・factor-spectrum・公開API・加工後配信テストに加え、今回の独立数値照合と旧コミット別実行の回帰検査を追加した。

## 固定試行シミュレーション

`tests/group-judge-simulation.mjs`。乱数種0x20261010、各ケース400反復、5台のBB/RB/その他を既存設定表から直接生成。通常は1台8,000G、低稼働のみ100G。差枚逆算の校正は行わず、差枚なしのボーナスモデルを検証する。

| 真の配分・観測条件 | 全456反証率 | 全56反証率 | 全6反証率 |
| --- | ---: | ---: | ---: |
| 12456 | 6.75% | 25.00% | 38.50% |
| 44556 | 0.00% | 2.50% | 4.75% |
| 55666 | 0.25% | 0.50% | 1.00% |
| 66666 | 0.25% | 0.50% | 0.50% |
| 66666の1台をBB10/RB6に固定 | 100% | 100% | 100% |
| 44556、100G/台 | 0.00% | 0.00% | 0.00% |
| 44556、5機種混在 | 0.50% | 1.75% | 7.00% |

反証判定は3チャネル・台数・3仮説を補正したfamilyP<.05。真の仮説に対する率はこの乱数で0〜0.50%だった。「弱い台」のケースは極端な観測を意図的に固定した反証動作確認で、誤反証率の測定ではない。

低設定2台を含む12456でも全456の反証率は6.75%に留まる。**反証なしを全台系の証明にしてはいけない。** この検査は下振れの強い矛盾を探す保守的検査で、設定1〜6の差が小さい場合や台数補正が大きい場合は検出力が低い。100G/台では平均対数根拠比も約0.03で、観測だけではほぼ区別できない。

別の固定例では、5台のうちミスター1台が8,000G・BB22・RB16で個別P4+は約3.47%。全456の補正p値は約0.082で、この検査では反証なし。全56は約0.0116、全6は約0.0030で反証ありとなった。5,000G・BB14・RB10の例は個別P4+約9.87%でも3仮説とも反証なし。通常の個別分布を変更せず、条件付きでは弱い台を設定4主体に説明することを検証した。仮説の成立を断言する例ではない。

## 蓄積済み観測データ

`tests/fixtures/group-pia-observed-20260921.json` は既存の調査アーカイブから生観測のみを抽出した106台（2026-09-21、PIA大船1、マイ48／ゴー24／アイム24／ファンキー5／ハッピー5）。その日の各機種の全観測台を採用し、見栄えのよい台だけを選ばない。既存判別出力や推測設定は正解として使わない。

各機種2〜60台の範囲でエンジンを実行できた。設定の確定ラベルはないため、正解率・イベント確率・実ホールでの誤反証率の校正には使用していない。差枚を含む比とボーナスだけの比が離れる場合があり、両者を別表示する理由になる。全6を条件にした配分666…の値が100%でも、全6の根拠比が非常に小さい場合がある。条件と成立可能性を区別する必要がある。

## 未校正の点と適用限界

- 既存のブドウ逆算は近似モデル。新しい根拠比にもその限界が残る。通常の個別判別の値は変更しない。
- 重みは宣言したモデル上の仮定で、店舗が全台系を行う事前頻度ではない。全456・全56・全6の成立確率は表示しない。
- ボーナス検査は固定の観測終了時刻・対象台集合を前提とする。結果を見て台を選別する場合や途中終了では解釈に限界がある。
- 同じデータの根拠比、反証検査、合算参考判別を追加の独立証拠として合成しない。機種混在に単一機種表を流用しない。
- 条件付き配分は等重みの下での推定。重み感度は根拠比に対して表示し、別重みの条件付き配分まで推定したように見せない。
- 全台系は2〜60台、1台10,000,000G以下。通常の個別判別の入力上限は変更しない。

## 再現方法

```sh
npm test
npm --prefix vps test
python3 tests/group-judge-independent.py
node tests/group-judge-simulation.mjs
node tests/group-judge-regression.mjs
node tests/parallel-group-browser.mjs
```

独立Python照合には検証環境のSciPyが必要。ブラウザ検証にはPlaywrightとChromium/WebKitの実行依存・日本語フォントが必要。任意のChromiumは `JUGEST_BROWSER_EXECUTABLE_PATH` で指定できる。`JUGEST_UI_EVIDENCE_DIR` はスクリーンショット出力先、`JUGEST_BROWSER_ENGINE` はchromium/webkit、`JUGEST_BROWSER_DELIVERY` はbuilt/patched、`JUGEST_BROWSER_WIDTHS` は320/375/390から絞り込む任意指定。ブラウザ検証はローカルの一時DB・ローカル配信を使用し、外部通信は遮断する。

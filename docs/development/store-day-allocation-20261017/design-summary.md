# JUGEST 店舗単日投入分析：実装判断の要点

2026年10月17日／設計フェーズ完了用資料。新機能は未実装。

## 推奨する構成

店舗と営業日を選ぶと、保存済みデータを機種別に分類し、高設定が**0台から全台までのすべてのケース**を比較する。

「12台のうち6台が好調だから半分投入」とは数えない。4台投入＋2台の上振れ、6台投入、8台投入＋2台の下振れも、台の割当ての全組合せを平均して比較する。

一覧では、機種・設置台数・推定台数の幅・全台系/半分以上/1/3以上・根拠・保留理由を表示する。詳しく見ると、各台の通常判別と、各投入仮説が説明できる点・できない点を確認できる。

## 今回確かめたこと

- GitHubの本番用ブランチと、実サーバーで動く版は `1f8c29f` で一致した。
- 過去完成版 `eb8a9e1` からは表示・説明の変更だけで、既存の全台系数学は同一だった。
- 既存の個別判別は設定別のログ尤度を内部に持つ。新機能用にそれを捕捉できるが、現在の公開MCP応答だけでは不足する。
- 店舗画面の「島の見立て」は、並列判別の全台系エンジンとは別モデル。新機能の投入確率に流用しない。
- PIA大船1の直近保存データには、106台のうち0Gが1台ある。未稼働台を消さず、情報がない台として設置台数に含める必要がある。
- 保存上の有効状態や原本参照だけでは、全台取得と実測項目を立証できない。元の欠損が0になる経路、端末データを原本として再包装する経路もある。

## 最も重要な設計判断

| 判断 | 推奨 |
|---|---|
| 何台投入か | 最有力1点に絞らず、0〜全台の分布と幅を見せる |
| 上振れ対策 | 通常配分だけでなく、少数投入側に最も有利な設定配置とも比べる |
| 百分率 | 初期の主表示には出さない。出す場合は事前配分・事前イベント確率・使用観測を明示 |
| 全6などのまとまり | 各台独立等重みだけでは極端に不利になるため、まとまった設定投入も含む共有モデルを比較 |
| 多数の候補探索 | 店内全機種と主要仮説を先に固定し、全体で偶然の候補増加を抑える |
| 差枚 | 通常の個別判別は維持。投入分析の主計算はボーナス、既存差枚モデルは別の参考として表示 |
| 不足・曖昧な0 | 数字を補わず、機種全体を保留。既知の0Gとは分ける |
| 既存機能への影響 | 個別q・既存全台系・PRE・予測・同期の意味を変えない |

## 解決できないことも機能に含める

単日データだけで上振れを完全に排除することはできない。厳密な全台系は、最後の1台が境界の下か上かを識別する必要がある。既存ネオアイムのボーナス表では、設定5と6のRB確率が同じで、BBも近い。終日でも「全6」と「1台だけ5」を高感度に区別するのは難しい。

慎重な比較では誤検出を抑える一方、見逃しが増える。候補にならなかったことを「高設定投入なし」と表示しない。実店舗での誤検出率は、新しい数学の証明や正解付き仮想データだけから確定しない。

## 検証とレビュー

今回、現行の既存テスト41件が成功。独立数値照合も二項分布412件・全設定列挙27件で一致した。これは既存機能の確認であり、新機能の精度保証ではない。

数学とシステム連携を別々にレビューし、事前配分の偏り、検出力、原本の来歴、全機種台帳、日付の厳密一致、同日訂正、認可、PREへの副作用を設計へ反映した。

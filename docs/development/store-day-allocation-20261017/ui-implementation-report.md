## 実装内容

- 既存「台」の隣に「投入分析」を追加。店舗・選択済み営業日を引き継ぎ、日付が履歴一覧にない場合も選択日を保持する。投入分析は従来の `getStoreDay` や最新日へのフォールバックを使わない。
- 一覧は設定4以上を既定にし、設定5以上・6へ切替可能。設置台数と確認台数、90%区間、仮定変更を含む範囲、期待台数、全台・半分以上・1/3以上、未稼働・低稼働・差枚の確認数を表示する。
- 9通りの固定感度比較が返す根拠比の対数が、許容差 `1e-10` を超えて正負の両側に残る場合、主要イベントを「仮定によって変わる」と表示する。根拠比の実際の幅を表示し、選択した「ちょうど指定台数」・「指定台数以上」についても、その条件自身の9通りを日本語で確認できる。入力から別の根拠比を計算せず、主計算の順位・比較する仮説数・正の慎重比較を追加しない。
- 各機種を縦カードで表示。不足、設置台数不明、未対応機種を残す。対応機種が完全でも未対応台の営業日が不確かな場合は、店舗全体の一部未確認を明示する。未対応台の不足理由も表示する。
- 一覧にイベント成立確率の百分率、強い候補、認定・確定のバッジを出さない。全台0Gは明確に情報不足と表示する。根拠比の対数が絶対値 `1e-10` 以下なら、丸め誤差による候補化を避けて「同程度・情報不足」とする。計算値そのものは変更しない。
- 機種詳細に台数分布、ちょうど指定台数と指定台数以上の切替、反対側との根拠比、主要イベントの慎重比較、通常3配分との比較、宣言された重み・台数事前・固定感度比較を表示する。正の慎重比較を登録していない固定台数は対象外と示す。
- 通常の各台qと、選択仮説を仮定した条件付き配分を別表示する。実測G・BB・RB・差枚、行ごとの不足理由・注意、比較への影響を示す。欠損値を0へ変換しない。
- 差枚込み参考は、主ボーナス計算と別のパネルで並べる。選択設定帯の期待台数・中央値・90%区間・感度範囲・根拠比、差枚確認数・実際の逆算使用数・警告数・計算経路とボーナスのみへのフォールバックを表示する。結果を加算・乗算せず、並び順・主計算の評価には使わない。参考側の慎重比較や強判定は表示しない。
- 非整数差枚は行の注意として「差枚が整数として確認できないため、差枚なしで計算しました」と表示する。ボーナス行の対象可否を変更しない。
- 分析状態は `this.allocation` の一時状態。保存済みUI値や同期ペイロードに分析結果を追加しない。日付・店舗・機種・仮説の変更、画面遷移、データ更新通知で不要な要求を中止し、要求世代と店日・データ版で古い結果を拒否する。
- 新分析だけ専用の cookie 読み取りクライアントを使用する。従来の解析クライアントの既定動作は変更しない。新しい店舗解決 `/api/vps/allocation/stores` と厳密な店日APIを使用する。読み取り利用者の未保存結果 `allocation_result_not_ready` は、所有者・管理者の計算が必要なことを日本語で案内する。
- VPSの Store UI v2 が元の店舗タブを置換するため、置換側にも投入分析を追加した。元のナビゲーション操作キーは保持。6タブは狭い画面で3列にする。

- 強い判定は無効。主計算・差枚込み参考とも実店舗の的中率を校正済みとは表示していない。営業終了を示す情報が応答にない場合は、終日と推測せず「終日・途中の区分未確認」と表示する。

## 実装時の判断

1. イベントの正式出力が配列だったため、ID参照を追加し、当初契約のオブジェクト形式も受け付ける。正式出力を取り違えると閾値・基準比較が欠けるため、実エンジン出力で回帰を固定した。
2. 「0台以上」は全空間で反対側がなくAPIの比較対象外なので、以上へ切替時は1台へ補正する。ちょうど0台は保持する。
3. 小さい根拠比の対数の表示許容差は数学の変更ではなく、情報なしを誤って候補と呼ばないための表示判断。ごく小さい正の差を候補ラベルにしなくなることが影響範囲。
4. 差枚込み参考は近似モデルなので、主計算とは合成しない。実際にボーナスのみへ戻った行や警告を隠さず、参考側の正の慎重比較を表示しない。

5. 感度の方向反転は既定の9通りの診断値を表示するもので、追加の探索や配分学習ではない。対数の正負が数値許容差の内側にしかない場合は反転と呼ばない。主モデルだけで見える候補ラベルが仮定依存のラベルに変わることが影響範囲。

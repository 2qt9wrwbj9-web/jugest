## 数学と意味の保存

既存runtimeのコールバックから設定別の観測尤度を直接取得する。設定事後確率を尤度へ変換し直さず、事前確率の二重計上を避けた。0Gは旧エンジンへ仮の1Gとして渡さず、新エンジン内で中立にする。

高設定台数kの尤度は係数DPで全配置を合計し、`choose(n,k)` で割る。対数空間で計算し、設定4以上、5以上、6の台数分布は同じ構成モデルから得る。既定モデルは4以上の台数0〜nを一様とし、高設定内の独立均等・純4・純5・純6の共有成分を各1/4で混合する。このため全6の事前は `(1+3^(-n))/(4(n+1))` となり、独立均等配分だけによる指数的な全6ペナルティを避ける。

根拠比は、指定仮説と補集合それぞれの**条件付き事前**による尤度の比。事後確率や的中率ではない。事後分布・90%区間は明示した構成事前を前提とする。通常比較3配分の重みはそれぞれ、低設定中心 `[.7,.2,.1,0,0,0]`、中間中心 `[.1,.2,.5,.15,.04,.01]`、一部高設定 `[.5,.25,.15,.06,.03,.01]`。実店舗の配分を学習した値ではない。

誤検出抑制用の証拠量は、事前固定の正規化済み対立分布Qを、指定条件を満たさない全設定配置の最大尤度で割る。`e≥M/.05` をモデル内通過とする。対応群の全台・半分・1/3の3設定帯を先に宣言し、同じ閾値は重複計上しない。任意のちょうど台数や感度分析には新しい正のe宣言を設けていない。

個別数学・確率表・通常q・期待設定・既存全台系・並列判別・PRE・過去傾向・翌日予測・同期・取得の意味は保存した。追加は独立モデルと尤度の読取境界。既存数学の別案への置換は行っていない。

仮想データの要点：

- 12台・各6,000G・店内9機種の検証で、全3や境界構成など各条件2,048店舗の誤ったモデル内通過は観測0。各条件の95% Wilson上限は0.1872%。実店舗で誤検出率0という意味ではない。全6条件は全宣言が真なので、そこで誤判定0を帰無検証と呼ばない。
- 検出力は低い。全台6の18,432機種群でも、全456・全56・全6の厳格な通過はそれぞれ0。半分以上456は2.65%、1/3以上456は17.17%。全4の真の456宣言も通過0であり、強候補表示の実用性能条件は未達。
- 真の1/3が6・残り3の構成で、`P(K456≥半分)≥.5` は78.44%。事後確率の固定閾値だけでは投入割合を誤って強調しうる。慎重比較の誤った半分通過は0だったが、その保守性は見逃しとの交換になる。
- 宣言した共有事前そのものから発生した検証群では、90%区間の被覆は456/56/6で95.41/96.77/96.92%。これはその事前と固定Gの範囲の診断で、任意の店舗配分への校正保証ではない。

数式の一致、モデル内の誤検出抑制、実店舗で有用な候補抽出性能は別の評価である。今回合格したのは計算・統合・参考表示の検証。強い自動認定は有効化していない。

最終のローカル性能確認は、2 CPUに固定し、原本確認・9感度・差枚参考・worker・保存結果読取までを含めた合成入力。58/60/120/1,000台の初回処理は約229/196/496/3,197ms、1,000台の保存結果読取は約162ms、観測RSS最大は約194MiB、応答JSONは8,169,057bytesだった。全テストとの同時実行では同じ1,000台が約5.1秒になったため、3.2秒を本番の保証値とはしない。CPU affinityは2 CPUだがコンテナーのquotaは8 CPU・8GiBで、2GiB制限下の実測ではない。イベントループの最大遅延約147msも記録し、Webの負荷確認を残す。

## 残存リスクと判断事項

1. **強い判定の検出力**：保守的な帰無最大化では全台系を頻繁に見逃す。実用化には検証の追加または別設計の検討が必要。既存設計の意味を変える案は別途承認対象。
2. **観測モデルの現実性**：仮想データは固定G・独立な多項分布・完全取得。好不調による遊技終了、営業途中、関連する欠損、設定変更途中、店内依存、差枚の観測誤差は校正していない。実店舗の正解設定は不明。
3. **原本の範囲**：全既存店日が分析可能とは限らない。PIAの隣接full snapshot、明示的全台HTMLなど立証できる形式に限定。再包装、曖昧な旧日、欠損原本、取得上限到達は保留する。
4. **ブラウザー**：WebKit導入はZIP展開とロック更新で失敗。Safari・iPhone実機は未確認で、本番反映判断時の残項目。
5. **キャッシュと権限**：標準はプロセス内メモリー。再起動・追い出し後、閲覧キー利用者は所有者/管理者の再計算待ち。永続結果ストアの部品はあるが、本番向け設定・作成・移行は行っていない。
6. **負荷**：1群120台まで。1,000台の合成原本で確認したが、本番の負荷・同時利用やネットワーク転送は未確認。大きい応答は約8.17MB。重い計算はworkerだが原本読取・JSON処理には同期部分がある。
